### M1 — Schemas, ports, prompts (2026-10-13)

- `schemas.ts`: all §6.1 contracts in zod, plus `ToolResult` (uniform `docs[]` or a friendly `{code,message}` error) and one output contract per prompt. `Report.partial` (default false) added for M9's partial runs.
- `ports.ts`: §6.3 interfaces + `Clock` and a `Ports` bundle.
- `prompts/*.md`: the five spec prompts verbatim; `llm_only.md` and `single_agent.md` written in the same style (spec names them but gives no text). Both baselines return a **verbal confidence**, which is what Satya's self-consistency confidence is compared against for ECE/AURC.
- `prompts/*.schema.json` are written from the zod contracts (`npx tsx scripts/write-prompt-schemas.ts`); a test fails if they drift, and another checks strict-mode compatibility (all properties required, `additionalProperties:false`) for Groq/Ollama structured output.
- `scripts/embed-prompts.mjs` → `packages/core/src/prompts.generated.ts` (committed; `--check` mode used by a test).
- Renderer: single-pass, values inserted literally (braces in user text can never become placeholders — this is how "escapes `{`/`}`" is implemented without altering the text the LLM sees), per-placeholder max lengths with ellipsis truncation, missing **and** unexpected values throw. Evidence renders as `[E1] (source, title) text…`; transcript keeps the last 2 turns per side (§9).
- **Tested:** `npm run check` → 5 files, 49 tests passed (core: 41). Includes a test that each spec prompt is byte-identical to its code block in `docs/Satya_Development.md`.

### M2 — Tools (2026-10-13)

- `packages/tools`: `wiki_search`, `wiki_page`, `arxiv_search`, `scholar_search`, `web_search` (Tavily), `fetch_url`; `createTools(ctx)` implements the core `Tools` port: zod-validated args (shared with MCP in M8), cache (`ToolCache`; memory impl here, SQLite in M6, ArchiveDO in M9, 72 h TTL), per-host politeness, friendly `{code,message}` errors — tools never throw.
- HTTP: configured User-Agent, 15 s per-request timeout, ≤ 2 retries on 429/5xx with full-jitter backoff honouring `Retry-After`, all inside an 18 s per-call budget (below the 20 s cloud tool-step timeout).
- `fetch_url`: http(s) only, no credentials, blocks loopback/private/link-local/CGNAT/metadata/IPv6 ULA+link-local/IPv4-mapped (incl. the hex form URL parsing produces) and `.local/.internal/localhost`/dotless hosts; redirects followed manually (≤ 5) and **re-validated each hop**; HTML only; body streamed and cut at `fetchMaxBytes`.
- HTML→text: both adapters feed explicit open/close/text events into one shared `TextCollector` (implied-end rules + entity decoding), because a workerd probe showed HTMLRewriter does **not** decode entities and does **not** report implied `</p>` — the shared collector makes the outputs identical by construction.

- **Observed:** at 150 KB a Wikipedia article's HTML is still all navigation (body begins later) — irrelevant for Wikipedia evidence (uses `wiki_page` plain-text API) but the researcher (M4) must not `fetch_url` Wikipedia links from web results.

### M3 — Retrieval (2026-10-13)

- `chunker` (220 words, 40 overlap, id = sha1(url#index)), own Okapi BM25 (k1 1.5, b 0.75, Lucene non-negative idf, Unicode tokeniser, English stop words), cosine on normalised Float32, `rrf(lists, k=60)` (ranks from 1).
- Pipeline split into two pure halves — `fuseCandidates` (BM25 top-20 ∪ dense top-20 → RRF → top-20) and `selectEvidence` (re-rank → top-5 as E1..E5) — so the Workflow can run `embed:c1` and `rerank:c1` as separate steps; `retrieveEvidence` composes them for the laptop. Accepts precomputed vectors and a prebuilt BM25 index (for the SciFact closed corpus in M6).
- `sha1Hex` in plain TS (incl. its own UTF-8 encoder) so core needs no runtime globals; verified against FIPS vectors and node:crypto (incl. Devanagari and emoji).
- Fakes + tiny corpus live in `@satya/core/testing` (shared with later packages).
- Laptop providers written early (needed for this acceptance): `OllamaEmbedder` (`/api/embed`, batches of 32) and `TransformersReranker` (`Xenova/bge-reranker-base`, fp32, CPU, batches of 8, max 512 tokens); transformers.js cache set to `D:\hf-cache	ransformers-js` (1.1 GB).
- **Tested:** hand-computed RRF (a: 1/61+1/62 = 0.0325225, …) and BM25 values; tiny-corpus test with fake cloud ports (4 queries) and with **real laptop models** (`npm run test:integration`): correct passage is E1 for 4/4 queries, ranked 1st by BM25, dense and re-ranker. Re-rank logits of the correct passage 6.6–10.2 vs ≤ 0.97 for the runner-up.
- **Measured:** bge-m3 via Ollama returns 1024-d vectors; the transformers.js re-ranker returns **raw logits** (negative values observed) — the judge's `sigmoid(max rerank)` must see logits in the cloud too (check Workers AI scale in M9, C13).

### M4 — Agents (2026-10-13)

- `callJson`: renders the prompt, sends the prompt's JSON schema, validates with zod, **one repair attempt** ("Return only valid JSON matching the schema"), then `bad_output`; one trace span per attempt (`<step>` / `<step>:repair`).
- Decomposer (ids c1.., `maxClaims` check-worthy cap, span via exact → case-insensitive → token-Levenshtein window ≥ 0.85), planner (trim/dedupe/cap; strips an echoed `scientific=true`), researcher (pure planners: one search per query × selected source, papers only when `scientific`; then top-3 Wikipedia titles round-robin + top-3 non-Wikipedia web URLs; dedupe docs by URL keeping the longest text; BM25 pre-filter to `maxPassages` = 60), debaters (citations = JSON list ∪ inline `[E#]`, only valid ids), judge (majority with NEI-first tie-break; uncited SUPPORTED/REFUTED majority → NEI; confidence = 0.7·agreement + 0.3·sigmoid(max re-rank logit of cited evidence); abstain < τ), aggregator (factuality).
- **Tested:** unit tests incl. the spec example (3× SUPPORTED, cited re-rank 1.0133 → confidence **0.920**) and an abstention just under τ (0.547 < 0.55). Coverage: `agents/judge.ts` 100 % lines, `retrieval` 96 % lines (target ≥ 75 %).
- **Real-model acceptance** (`apps/cli/test/agents.integration.test.ts`, log `results/acceptance/m4-agents.log`): run 1 passed. Run 2 exposed a real defect: a Qwen3 judge sample hit the 3,072-token cap while thinking and returned empty content. Probe (same prompt, 3 seeds): 1/3 truncated at 3,072. Fix: thinking tasks use `num_predict −2` (fill remaining context; KV cache is fixed at num_ctx 8192, so VRAM is unchanged). Re-probe over 10 seeds: **10/10 valid JSON**, thinking median 1,961 tokens (max 3,205), median 27.4 s (max 46.0 s) per judge sample; non-thinking calls take 2–3 s.
- **Implication for M7:** judge thinking dominates laptop time (~3 × 27 s per claim) — the full evaluation is a multi-day run; τ tuning and all systems use the resumable SQLite store.

### M5 — Pipeline steps + local runner (2026-10-13)

- `RunState` is plain JSON; every step returns a serialisable `StatePatch` (what a Workflow `step.do` must return) and `applyPatch` folds it in purely. `planSteps(state)` returns the frontier in deterministic order (claims in input order, ≤ `parallelClaims` = 2 claims in flight); the runner executes a frontier concurrently and applies patches in frontier order, so the step **sequence** is timing-independent.
- Step names: `decompose`, `plan:c1`, `search:c1:q2:wiki`, `fetch:c1:3`, `embed:c1`, `rerank:c1`, `argue:c1:r1:advocate`, `judge:c1:s2`, plus `verdict:c1` (pure; aggregates samples and emits the verdict event as soon as a claim is done) and `aggregate`.
- Baselines/ablations are `Variant` presets over the same steps (`llm_only`, `single_agent_rag`, `satya_no_debate`, `satya_full`, `dense_only`, `no_rerank` (scores 0 → RRF order; strength = sigmoid(0)), `rounds_1`, `rounds_3`); closed-corpus mode skips plan/search/fetch and fuses against a prebuilt corpus index.
- Per-claim step failure → NEI `pipeline error`, run continues; `decompose` failure → `run_failed`. `capacity` patch → remaining claims NEI `capacity`, report `partial`.
- "step n of ~N" estimator uses exact counts once searches/fetches are planned and reports exactly N at completion.
- **Tested:** golden test — `runLocal` walks exactly `GOLDEN_STEPS` (30 steps, in `@satya/core/testing`, reused by the Workflow parity test in M9); forced tool failure completes; a throwing claim step yields `pipeline error` while the other claim finishes; variants run the expected step lists. `npm run check`: 170 tests green.

### M7 — Evaluation harness (2026-10-13)

- `eval/datasets.ts`: SciFact 1,109 (456 SUPPORTED / 237 REFUTED / 416 NEI; no claim has both SUPPORT and CONTRADICT, ids unique), FEVER 600 balanced (seed 13), HoVer 300 balanced (seed 13); split 30/70 with a seeded (mulberry32) **stratified** shuffle → SciFact 333 dev / 776 test, FEVER 180/420, HoVer 90/210, no overlap.
- Systems = `Variant` presets (M5). Evaluation starts from the claim. SciFact uses the closed corpus; FEVER/HoVer use Wikipedia tools only (C7).
- Results: one row per item in SQLite (resumable, keyed by dataset:system:split:configHash; τ excluded from the hash), exported to `results/<dataset>_<system>_<split>_<ts>.jsonl` + `.summary.json`. Items store ids, gold/raw labels, confidence, samples, cost — **no dataset text** (C17). Step error messages are kept for diagnosis.
- Metrics (`packages/core/metrics`, hand-checked unit tests): accuracy, macro-F1, confusion, ECE (10 bins), reliability bins, risk–coverage + AURC, selective accuracy/coverage at τ, τ tuning. **τ is applied post hoc** (final label = NEI when confidence < τ): accuracy/F1 use final labels; ECE/AURC use raw label + confidence. HoVer: REFUTED/NEI → NOT_SUPPORTED.
- `tune`: τ from pooled satya_full **dev** results maximising selective accuracy at coverage ≥ 0.7 → `configs/default.json` + `results/TAU.json`. `report`: `results/SUMMARY.md` (Project §9 tables + per-dataset detail + SciFact ablations; best value bold; missing = "—") and `results/benchmarks.json` (web).
- Ollama adapters retry transient failures (≤ 2, exponential backoff) like the gateway does in the cloud — one transient failure appeared in the first smoke run (0/40 on reruns).
- **Acceptance** (`results/acceptance/m7-eval-llm-only.txt`): `npx satya eval --dataset scifact --system llm_only --limit 20` under the offline guard → completed, 0 network attempts, exported JSONL + summary (20-item smoke numbers are not results).
- **Measured cost per claim (laptop):** llm_only ≈ 2.4–4.6 s; satya_full ≈ 110–170 s (M4/M6 logs; 3 thinking judge samples dominate). Full evaluation plan ≈ 7–8 days of GPU time; runs in the background, resumable.
